## 5. 스크린샷 문구

6.9인치(iPhone) 필수, 6.5인치는 6.9인치로 대체 가능. Play는 휴대전화 스크린샷 2~8장.

| 순서 | 화면 | 큰 문구 | 작은 문구 |
|---|---|---|---|
| 1 | 고르기 (날짜별 사진, 몇 장 선택됨) | 오늘 찍은 사진 중, 몇 장만 | 십 년 뒤에도 보고 싶은 사진을 골라요 |
| 2 | 기록 화면 (사진 + 메모) | 사진에 그날의 기억을 | 메모와 장소를 함께 남겨요 |
| 3 | 앨범 이야기 보기 | 다시 보고 싶어지는 사진첩 | 메모와 함께 한 장씩 넘겨 봐요 |
| 4 | 앨범 연도 보기 → 월 보기 | 몇 년이 지나도 한눈에 | 연도부터 하루까지 당겨 봐요 |
| 5 | 사진첩 탭 (그날의 기억 + 앨범들) | 몇 년 전 오늘을 다시 | 내가 만든 앨범으로 묶어요 |
| 6 | Cloud 화면 | 남긴 사진은 지키고, 휴대폰은 가볍게 | 새 휴대폰에서도 그대로 (선택 구독) |

스크린샷용 데이터는 실제 개인 사진이 아닌, 직접 찍은 풍경·음식 사진이나 사용권이 있는 사진으로 만든다.

## 6. App Store 개인정보 보호 라벨 (App Privacy)

추적(Tracking): **하지 않음**. 광고 SDK와 다른 회사 앱·웹을 넘나드는 데이터 결합이 없다.

수집하는 데이터 (Cloud 사용자만 해당. 모두 '사용자와 연결됨', 목적은 '앱 기능'):

| 유형 | 항목 | 메모 |
|---|---|---|
| 연락처 정보 | 이메일 주소 | 로그인 시 Apple·Google이 준 경우 |
| 사용자 콘텐츠 | 사진 또는 비디오, 기타 사용자 콘텐츠(메모) | Cloud 백업 |
| 위치 | 정확한 위치 | 사진 EXIF 좌표를 기록과 함께 백업. 기기 현재 위치는 읽지 않지만 라벨 정의상 해당한다 |
| 식별자 | 사용자 ID | 서버 계정 ID, RevenueCat app_user_id |
| 식별자 | 기기 ID | 재설치 후 사진 연결 복구용 기기 구분값(해시) |
| 구입 항목 | 구입 내역 | RevenueCat 구독 확인 |
| 진단 | 충돌 데이터, 기타 진단 데이터 | 앱은 계정을 지정하지 않지만, 네이티브 충돌 이벤트에 Sentry 설치 ID가 붙는다 (2026-11-02 확인). 제출 전 라벨 분류를 다시 판단한다 |

Local만 쓰면 서버로 가는 데이터가 없지만, 라벨은 앱 전체 기준이라 위 항목을 모두 적는다. 기기 운영체제의 주소 변환(Apple CLGeocoder)은 개발자가 받는 데이터가 아니므로 라벨에 넣지 않는다.

| 질문 | 답 |
|---|---|
| 데이터를 수집하거나 공유하나요 | 수집함, 공유 안 함 (위탁 처리업체는 '공유'가 아님) |
| 전송 중 암호화 | 예 (HTTPS) |
| 데이터 삭제 요청 방법 | 앱 안에서 계정 삭제 가능 + 웹 삭제 요청 주소 {{필수: 앱을 지운 사람도 요청할 수 있는 웹페이지 또는 이메일 안내}} |

| 기기 또는 기타 ID | 수집, 선택(Cloud 사용 시), 앱 기능 |
