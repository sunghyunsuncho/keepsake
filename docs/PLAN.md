| 고르기 방식 | 필름 한 롤을 넘겨 보듯, 지난번에 살펴본 다음 사진부터 이어서 보여준다. 지난 사진은 오래된 순서로 세로 스크롤하며 연도·월·일 중 고른 밀도로 다시 고른다 |

| Local 범위 (2026-10-30) | Local은 이 기기 안에서만 관리한다. ZIP 내보내기·가져오기와 기기 간 연결 다시 잇기는 하지 않는다. 기기를 바꿔도 기록을 이어 가려면 Cloud |
| 사진 정리 (2026-11-02) | 고르기를 마치면 살펴보고 남기지 않은 사진을 지울지 묻는다. 기본은 지우지 않음이고, 정리 화면과 OS 확인 창을 모두 거쳐야 지운다. 남긴 사진은 대상에서 뺀다. 습관의 목적이 사진을 줄이는 것인데 지우는 흐름이 없었기 때문이다 |
| 안전 앨범 (2026-11-05) | 안전 사진첩은 안전 앨범 목록이다. 기기 앨범을 연결하거나(이후 기기 앨범에 넣는 사진도 따라 담음, 빼기는 따라 하지 않음) 안전 보관에만 있는 앨범을 만들고, 나의 순간들에서 사진을 골라 담는다. 사진은 안전 앨범에 담긴 기록만 올린다. 보관 화질은 앨범마다 고른다: **원본 그대로**(원본 + 표시용) 또는 **효율 보관**(표시용 긴 변 1600px만). 주어진 용량을 사용자가 효율적으로 쓰게 하려는 것이다. 안전 앨범에서 빼거나(앨범 지우기 포함) 효율 보관으로 바꾸면 다른 안전 앨범에 필요 없는 사진은 서버에서 지운다 (`POST /photos/delete`). 기록은 남는다 |
| Cloud의 가치 (2026-11-02) | '백업'이 아니라 '남긴 사진은 지키고 휴대폰은 비운다'로 내세운다. 구글 포토·iCloud의 전체 백업과 경쟁하지 않는다. 가격도 이 기준으로 낮은 쪽을 검토한다 |

### 0.1 용어

| 용어 | 뜻 |
|---|---|
| 기기 사진첩 | 휴대폰의 사진 앱 (iOS 사진, Android 갤러리). 사용자의 원본이 있는 곳 |
| 고르기 | 기기 사진첩의 사진을 넘겨 보며 남길 사진을 선택하는 단계 (고르기 탭) |
| 남기기 | 고른 사진을 Keepsake 기록으로 등록하는 것 |
| 기록 (moment) | 남긴 사진 한 장 + 메모·장소·날짜. 사진은 기기 사진첩 원본을 가리키는 연결(`source_asset_id`)로 갖는다 |
| 기기 사진첩 | 이 기기에 남긴 `나의 순간들`과 사용자가 만든 앨범을 보는 탭. `나의 순간들`은 어느 앨범에도 담지 않은 개인 기록까지 포함한 전체 보기다 |
| 안전 사진첩 | 로그인한 계정의 안전 보관 공간을 보는 탭. 구독 중이거나 유예 기간에만 연다. 사용한 용량, `안전 보관한 모든 사진`(Cloud에 사진이 있거나 안전 앨범에 담은 기록), 안전 앨범 목록을 보여 준다 |
| 안전 앨범 | 안전 사진첩의 앨범 (`albums.kind = 'cloud'`). 앨범마다 보관 화질(`photo_quality`: `original`/`display`)이 있고, 기기 앨범을 연결해 만들었으면 `source_album_id`로 그 앨범을 가리킨다 |
| 앨범 | 사진을 함께 고르고 보는 장소. 한 기록이 여러 앨범에 들어갈 수 있고, 최신 사진·앨범 사진·기본 디자인 중 표지를 정한다 (`album_moments`가 연결만 둔다. 사진·기록을 복사하지 않음) |
| 지워진 사진 | 기기 사진첩에서 원본이 지워진 기록. Local은 메모·장소·날짜만 남고, Cloud는 Cloud 사본을 보여준다 |

## 1. 언어 분담

React Native/Expo 앱은 TypeScript로만 작성할 수 있다. 따라서:

- **Python (FastAPI)**: 데이터 모델, 구독 상태·용량 규칙, 백업/동기화
- **TypeScript (Expo)**: 화면, 로컬 저장, API 호출. 규칙을 넣지 않고 얇게 유지
- **타입 공유**: Pydantic 모델 → FastAPI OpenAPI → `openapi-typescript`(또는 `orval`)로 TS 타입과 클라이언트를 자동 생성

업로드 허용 여부(구독 중인지, 용량이 남았는지)는 **항상 서버가 판단**하고, 앱은 서버가 준 결과를 보여주기만 한다.

## 2. 요금제 설계

### 2.1 등급

| | **Local** (무료, 로그인 없음) | **로그인 기록 백업** (무료) | **안전 보관** (유료 구독) |
|---|---|---|---|
| 선택·기록·사진첩·다시 보기 | ✅ | ✅ | ✅ |
| 사진 | 기기 사진첩 원본을 가리킴 (기기 사진첩에서 지우면 사라짐) | 같음 | 안전 앨범에 담은 사진은 Cloud에도 보관 |
| 클라우드 백업 | ❌ | 기록·앨범 | 안전 앨범의 사진(원본 + 표시용 또는 표시용만) |
| 새 기기 복원 | ❌ (이 기기 전용) | ✅ 기록·앨범 | ✅ 기록·앨범·보관 사진 (Apple 로그인은 iOS에만 있어 Android로는 Google 계정만, §9) |
| 여러 기기 동기화 | ❌ | ✅ 기록·앨범 | ✅ 기록·앨범·보관 사진 |

- 핵심 경험(선택 → 기록 → 다시 보기)은 등급과 관계없이 모두 제공한다.
- 유료로 사는 가치는 "소중한 원본을 안전하게 맡긴다"는 것이다. 그래서 Local은 원본을 따로 지키지 않는다: 기기 사진첩에서 지우면 기록의 사진이 보이지 않는다고 미리 안내하고, 이게 싫으면 Cloud를 권한다.
- Local은 이 기기 안에서만 관리한다. 로그인 기록 백업은 기기를 바꿔도 기록을 잇고, 유료 안전 보관은 사진 원본까지 지키는 가치로 둔다. (휴대폰 자체 백업에 DB가 들어갈 수는 있지만 사진첩 연결은 기기마다 달라서 약속하지 않는다.)
- 화질 기준 하위 유료 등급은 출시 후 가격 저항 데이터를 보고 결정한다. 서버의 `PlanLimit.allow_original`로 구분할 수 있게 구조만 열어둔다.

### 2.2 원가 추정 (R2 기준)

R2 단가: 저장 $0.015/GB·월, 쓰기 $4.50/백만 건, 읽기 $0.36/백만 건, **이그레스 무료**, 매월 10GB 무료.

하루 3장씩 1년 기록할 때 약 1,100장:

| | 1장 크기 | 1년 누적 | 월 저장 비용 |
|---|---|---|---|
| 원본 (HEIC/JPEG) | ~3~5MB | ~4.5GB | ~$0.07 |
| 표시용 리사이즈본 | ~0.5MB | ~0.55GB | ~$0.008 |

이그레스가 무료라 다시 보기·복원에 추가 비용이 없다. 가격은 원가보다 앱스토어 수수료(15~30%)와 운영비를 기준으로 정한다.

### 2.3 결제 구현

- 디지털 서비스 구독이므로 **Apple/Google 인앱 결제가 필수**다 (외부 결제 불가).
- **RevenueCat** (`react-native-purchases`, Expo dev build 지원) 사용:
  - 앱: 페이월, 구매, 구매 복원
  - 서버: RevenueCat **웹훅**을 FastAPI에서 받아 `entitlements` 테이블을 갱신
  - 앱이 보낸 "나 구독 중이야"는 믿지 않는다. 서버는 웹훅 + RevenueCat REST API 조회 결과만 신뢰한다.
- RevenueCat `app_user_id` = Keepsake 서버의 `user_id` (로그인 후 `Purchases.logIn(user_id)`).
- 앱스토어 결제 실패 유예(Apple Billing Grace Period, Google 계정 보류)를 켜두고, 그 기간에는 구독 중으로 취급한다.

### 2.4 상태 변경 정책

| 상황 | 동작 |
|---|---|
| Local → 로그인 기록 백업 | 소개·가격 확인(로그인 없이) → 로그인 → 계정 공간으로 전환 → 아직 묻지 않은 Local 기록이 있으면 올릴 기록 선택 (처음 쓰는 계정은 전체 선택, 내용이 있는 계정은 전체 해제) → 고른 기록과 앨범을 백업. Local 기록은 그대로 남는다 |
| 로그인 기록 백업 → 안전 보관 | 구독 → 안전 앨범을 만들거나 기기 앨범을 연결 → 앨범에 담은 사진만 선택한 화질로 업로드 |
| 계정 공간 | 계정마다 기기 안에 DB 파일을 따로 둔다. 로그인 중에는 그 계정의 기록만 보이고(오프라인 포함), 새 기록도 계정 공간에 쌓인다. 로그아웃하면 Local로 돌아간다. 설정은 기기에 하나다 |
| 기기 사진 연결 | 고르거나 새로 남긴 기록의 사진 id를 계정·기기별로 서버에 저장해 재설치 후 복구한다. 파일 이름과 촬영 시각이 맞을 때만 잇고, 못 이으면 Cloud 사진을 보여준다. 다른 기기에는 내려주지 않는다 |
| 구독 만료 (스토어 결제 유예까지 끝난 시점) | 즉시 새 사진 업로드 중단. **30일 동안 사진 읽기와 전체 다운로드만 허용**. 기록 동기화는 계속 |
| 유예 중 알림 | 만료 즉시, 삭제 7일 전, 삭제 1일 전 (푸시 + 이메일) |
| 유예 중 재구독 | 아무것도 다시 올리지 않고 즉시 복구 |
| 유예 중 새 기록 | 기록은 백업하고 사진은 올리지 않는다. 재구독하면 안전 앨범의 사진이 올라간다 |
| 유예 30일 경과 | 사진(R2 객체 + `cloud_objects`)만 삭제한다. 기록과 계정 공간은 그대로 두고, 사진이 있던 기록의 변경 번호를 올려 기기가 '올라감' 표시를 버리게 한다. 다시 구독하면 안전 앨범의 사진을 다시 올린다 |
| 용량 한도 초과 | 신규 업로드만 중단. 기존 백업은 삭제하지 않음 |
| 계정 삭제 | 서버 데이터와 R2 객체 즉시 삭제. 유예 만료와 같은 기준으로 Local로 옮기고 전환 |

리사이즈본도 함께 올리는 이유: 새 기기에서 복원할 때 사진첩을 빠르게 먼저 보여주고, 원본은 필요할 때 받는다. 원가 증가는 약 10%다.

## 3. 아키텍처

```
[ Expo 앱 ]                                     [ FastAPI (Python) ]
 expo-media-library ─▶ 날짜별 선택                ├─ Auth: Apple / Google → JWT
 expo-image         ─▶ 기기 사진첩 원본을 그대로 표시 ├─ Sync: push(upsert) / pull(since=)
 expo-image-manipulator ─▶ 업로드 때 리사이즈본 생성 ├─ Upload: 구독·용량 검사 → presigned URL
 expo-sqlite        ─▶ moments, albums, ...       ├─ Upload complete: R2 HEAD로 크기 검증
 react-native-purchases ─▶ 구독                   ├─ Billing: RevenueCat 웹훅
        │                                          └─ Jobs: 유예 알림, 만료 데이터 삭제
        │  메타데이터 (HTTPS, JWT)                         │
        ├─────────────────────────────────────────▶ PostgreSQL
        │  사진 바이트 (presigned PUT/GET, 서버 미경유)      │
        └─────────────────────────────────────────▶ Cloudflare R2 (비공개 버킷)
```

### 3.1 R2 업로드 흐름

R2는 S3 호환 API라 Python에서는 `boto3`로 다룬다. R2는 presigned POST 정책(업로드 크기 제한 조건)을 지원하지 않으므로, **업로드 후 서버가 검증**한다.

1. 앱 → `POST /uploads` `{moment_id, variant: "display"|"original", size, content_type, md5}` (MD5는 파일을 JS 메모리에 올리지 않고 네이티브로 계산한다)
2. 서버: 로그인·구독 상태 확인(`active`만 허용, `grace`는 거절), 용량 확인 → `cloud_objects` 행을 `pending`으로 생성 → `Content-MD5`까지 서명한 presigned PUT URL(만료 10분)과 붙일 헤더 반환
3. 앱 → R2로 직접 PUT (내용이 MD5와 다르면 R2가 거절)
4. 앱 → `POST /uploads/{id}/complete`
5. 서버: R2 `HEAD`로 실제 크기와 ETag(MD5) 확인 → 신고한 값과 다르면 객체 삭제 후 거절, 정상이면 `stored`로 바꾸고 사용량 반영
6. 일정 시간 지난 `pending` 행은 정리 작업이 R2 객체와 함께 삭제

다운로드는 `GET /moments/{id}/photo?variant=` → presigned GET URL(짧은 만료). `active`와 `grace` 상태 모두 허용.

객체 키: `u/{user_id}/m/{moment_id}/{variant}-{token}.{ext}` (업로드마다 다르다). 사용자별 prefix라 유예 만료·계정 삭제 시 prefix 단위로 지운다.

### 3.2 동기화 규칙 (처음부터 적용)

- ID는 클라이언트에서 UUID로 생성
- 모든 행에 `updated_at`, 삭제는 `deleted_at`(soft delete)
- 충돌은 `updated_at` 기준 최신 우선 (개인용 앱이라 이 정도로 충분)
- `POST /sync/push`: 변경분 일괄 upsert (`active`만) / `GET /sync/pull?since=`: 이후 변경분 (`active`, `grace`)

### 4.2 서버 (PostgreSQL)

서버에는 로그인한 사용자가 존재한다. 기록 동기화는 로그인만으로 쓸 수 있고, 사진 객체는 구독 중인 사용자의 안전 앨범에서만 보관한다.

```python
class User:           id, email, created_at, deleted_at
class AuthIdentity:   user_id, provider ('apple'|'google'), subject
class Entitlement:    user_id, plan ('cloud'), status ('active'|'grace'|'expired'),
                      expires_at, grace_until, source ('revenuecat'), updated_at
class Moment:         id, user_id, taken_at, lat, lng, place_name, memo,
                      created_at, updated_at, deleted_at
class Album / AlbumMoment / ReviewSession: 기기 스키마와 동일 + user_id
class CloudObject:    id, user_id, moment_id, variant ('display'|'original'),
                      r2_key, size_bytes, md5, status ('pending'|'stored'|'deleting'),
                      created_at
class Usage:          user_id, bytes_total, object_count  # 집계 캐시
class PlanLimit:      plan, max_bytes, allow_original, grace_days (=30)  # 설정값
class BillingEvent:   id, raw_payload, received_at, processed_at  # 웹훅 원본 기록
```

- **구현 메모:**
  - Cloud 화면은 가격까지 로그인 없이 보여준다 (RevenueCat 익명 사용자로 상품만 불러온다). 구매·복원은 로그인한 뒤에만 해서 결제가 항상 서버 `user_id`에 묶인다. RevenueCat 키가 없으면(결제 연결 전) 로그인 버튼만 보여준다.
  - `CLOUD_BILLING_ENABLED=false`면 저장된 구독 상태가 `none`인 계정을 `active`로 보여주고 허용한다 (`app/cloud.py`의 `subscription_status`). 저장 값은 바꾸지 않으므로 true로 바꾸면 바로 결제 규칙으로 돌아간다. `ENV=production`에서 false면 서버가 시작하지 않는다. 앱은 RevenueCat 키가 없으면 구독 관리 버튼과 해지 안내를 숨긴다.
  - 구독 상태 `none → active → grace(30일 읽기 전용) → expired(삭제됨)`. `BILLING_ISSUE`·`CANCELLATION`은 상태를 바꾸지 않는다 (스토어 결제 유예 중이거나 만료 전이므로). `REVENUECAT_API_KEY`가 있으면 webhook마다·구매 직후(`POST /account/refresh-subscription`)·삭제 직전에 RevenueCat REST로 다시 확인한다.
  - 사용량·사진·변경 번호를 바꾸는 요청(push, 업로드 시작·완료)은 모두 사용자 행을 먼저 잠근다. 같은 사용자의 요청이 차례로 처리되어 사용량이 어긋나거나 교착이 생기지 않는다.
  - 기기는 기록을 고칠 때 updated_at을 이전 값보다 항상 뒤로 잡는다. 기기 시계가 조금 늦어도 방금 받은 값을 고친 수정이 서버에서 '옛 값'으로 버려지지 않는다. 서버 시각(마이크로초)은 받을 때 기기 형식(밀리초, `toISOString`)으로 바꿔서 문자열 비교가 맞게 한다.
  - pull 커서는 기기 시각이 아니라 서버가 매기는 사용자별 변경 번호(`users.sync_seq`)다. 사진 업로드가 끝나도 번호를 올려서 다른 기기가 표시용 사진을 받으러 온다.
  - 서버는 기기 전용 값(사진첩 연결 `source_*`, `sync_state`, 업로드 여부)을 저장하지 않는다. 사진첩 사진 id는 기기마다 다르기 때문이다.
  - 사진은 안전 앨범에 담긴 기록만 올린다 (2026-11-05, §0 '안전 앨범'). 표시용은 안전 앨범에 담긴 기록 모두, 원본은 화질이 '원본 그대로'인 안전 앨범에 하나라도 담긴 기록만 올린다. 기록 메타데이터 동기화는 로그인한 계정 모두에게, 계정 공간 전체를 맞춘다. 동기화 한 바퀴는 push → pull → 필요 없어진 사진 지우기 → 업로드 순서다 (다른 기기가 담은 사진을 지우지 않도록 받은 뒤에 지운다). 안전 앨범 전에 올린 사진은 계정 공간마다 처음 한 번 '이전에 보관한 사진' 안전 앨범에 담아 지워지지 않게 한다.
  - 업로드는 기기 사진첩에서 원본을 읽어 올리고, 표시용 사진은 그때 만들어 올린 뒤 지운다 (앱은 사진을 보관하지 않음). 사진첩에서 지워진 기록(`source_missing`)은 올리지 않는다.
  - 다른 기기에서 남긴 기록과 지워진 사진은 볼 때 Cloud 표시용 사진을 한 장씩 받아 캐시에 둔다. 크게 볼 때는 Cloud 원본을 서명 URL로 바로 그린다. 설정의 [Cloud에만 있는 원본을 기기 사진첩에 저장]은 원본을 기기 사진첩에 저장하고 기록을 그 사진에 잇는다 (새 기기, 구독 만료 후 30일 안의 전체 다운로드). 같은 파일 이름·촬영 시각의 사진이 이미 있으면 저장하지 않고 잇기만 한다.
  - moments 외 테이블(review_sessions, albums, album_moments)은 서버 `sync_records`에 같은 규칙으로 저장한다.
  - 기록을 지우면 사진은 `deleting` 상태가 되어 사용량에서 바로 빠지고, 주기 작업이 R2에서 지운다.
  - 계정 삭제는 요청 즉시 R2 prefix와 서버 행을 지운다. 스토어 구독은 서버가 해지할 수 없으므로 앱이 구독 관리로 안내한다.
  - 기기의 동기화 표시(`sync_state`, 업로드 여부, pull 커서)는 계정 공간 DB에 있다. 구독 유예가 끝나도 서버 기록은 지우지 않고 사진만 지우므로 계정 공간도 그대로 쓴다. 계정 삭제를 알리는 401을 받으면 이 기기 사진의 기록을 Local로 옮기고 공간을 비운다. 로그아웃은 공간을 그대로 두므로 다시 로그인하면 이어서 쓴다.
  - 서버에 저장된 사진은 덮어쓰지 않는다 (`POST /uploads`가 409, 앱은 올린 것으로 처리). 끝나지 못한 재업로드가 같은 키의 백업을 지우는 일을 막는다.
  - 유예 삭제 직전에 구독 상태를 조회하고, 조회에 실패하면 지우지 않는다. 만료 시각이 지난 active 구독은 주기 작업이 다시 조회한다. 유예 30일은 만료를 알아챈 시점부터 보장한다.
  - 계정 삭제는 R2와 RevenueCat 고객 정보를 지운 뒤 계정 행을 지운다. 중간에 실패해도 앱에는 성공으로 알리고 `deleted_at`으로 막은 채 주기 작업이 다시 한다. 삭제 전에 받은 업로드 URL로 늦게 올라온 객체는 `storage_cleanups`로 한 번 더 지운다. 앱은 401 `account unavailable`을 받으면 기기 기록을 Local로 옮긴다. 결제 이벤트 원본은 5년 뒤 지운다.
  - 라이브러리 패치 (`mobile/patches`, `postinstall`): `expo-sqlite`는 공간을 바꿀 때 진행 중인 쿼리가 닫힌 연결에 닿아 앱이 죽어서(SIGSEGV) 이전 연결을 닫지 않는다. `expo-media-library`는 촬영일이 없는 Android 사진이 날짜 조건에서 빠져서 수정 시각으로 대신한다 (소스에서 빌드하도록 `package.json`에 지정).
  - 사진 연결 복원: 일부 사진만 허용한 상태면 완료로 표시하지 않고, 볼 수 있는 사진 수가 달라졌을 때나 한 시간에 한 번 다시 시도한다.
  - 재설치: iOS Keychain은 앱을 지워도 남으므로, 앱과 함께 지워지는 표시 파일이 없으면 첫 실행 때 세션과 공간 값을 지운다. 다시 로그인해야 한다. 기기 구분값(사진 연결 복원용)은 일부러 남긴다. 표시 파일이 없던 빌드에서 업데이트하면 한 번 로그아웃된다.
  - 공간을 떠난 계정 DB 파일은 연결을 닫지 않으므로 다음 실행에서 지워진다. 남길 기록을 옮기다 실패하면 `retiring_spaces`에 남아 다음 실행 때 다시 옮긴다.
  - 사진 객체 키는 업로드마다 다르다 (`{variant}-{token}.{ext}`). 늦게 도착한 옛 URL의 PUT이 저장된 사진을 덮어쓰지 못한다. 대체된 키와 삭제된 계정의 prefix는 `storage_cleanups`로 URL 수명 + 1시간 뒤에 지운다. 멈춘 업로드 행의 정리도 같은 시간을 기다린다.
  - `lock_user`는 잠근 뒤의 최신 값을 돌려준다. 계정 삭제가 시작되면 쓰기 요청은 401 `account unavailable`이다. 표시(`deleted_at`) 저장이 실패하면 앱에 실패로 알리고, 그 뒤 정리 실패는 성공으로 알린 채 주기 작업이 이어서 한다. RevenueCat의 4xx 거절은 경보만 남기고 삭제를 막지 않는다.
  - 만료 시각이 1일 지난 active 구독만 다시 조회한다 (갱신 지연 여유). RevenueCat 조회가 연속 3번 실패하면 재조회와 유예 만료 삭제 모두 그 실행을 멈춘다. 삭제 표시된 계정은 알림·재조회·유예 삭제 대상에서 뺀다.
  - 유예 삭제는 삭제 직전 경고를 보낸 뒤 12시간이 지나야 한다 (작업이 멈췄다 재개된 경우 포함). 알림 전달에 실패하면 단계를 저장하지 않아 다시 보내고, 장애가 길어지면 유예 종료 7일 뒤에는 지운다. R2 객체는 DB 커밋 뒤 잠금 없이 `storage_cleanups`로 지운다. 멈춘 업로드·대체된 업로드는 키 하나, 유예 삭제는 계정 prefix 하나를 남기고, 정리 때 그 시각 이후에 올라온 객체와 `cloud_objects`에 있는 키(재구독 뒤 새 사진)는 남긴다. 계정 삭제는 prefix 전체를 지운다. 정리도 R2가 연속 3번 실패하면 그 실행을 멈춘다.
  - 토큰이 만료돼도 서명이 맞으면 계정 삭제 여부(`account unavailable`)를 알려 줘서 기기가 기록을 옮긴다.
  - 알고 둔 한계: 다른 기기에서 계정을 지우면, 세션이 남은 기기의 RevenueCat SDK가 저장해 둔 ID로 초기화되며 지운 고객을 빈 기록으로 다시 만들 수 있다 (구매 내역 없음, 무작위 ID뿐. 바로 로그아웃해 이후 쓰이지 않는다. SDK가 저장된 ID 없이 시작하는 방법이 없다). 로그아웃한 기기는 다른 기기의 계정 삭제를 알 수 없어, 그 계정 공간 파일이 남고 다시 들어갈 수 없다. 앱은 401 `account unavailable`을 계정 삭제로 믿는다 (서버를 빈 DB로 잘못 배포하면 공간이 정리된다. 배포 절차로 막는다). 일부 허용 상태에서 허용하지 않은 사진은 재시도 간격을 두고 올릴 대기로 남는다. Android 촬영일 대체 식은 색인을 쓰지 못한다 (날짜 범위 조회 비용, 5만 장 기기에서 확인 필요).
  - Google 로그인은 `@react-native-google-signin/google-signin`(네이티브). 토큰의 aud는 웹 클라이언트 ID다.

  - AAB를 올린 뒤 Play 앱 서명 키 SHA-1로 Google OAuth Android 클라이언트를 하나 더 만든다 (스토어에서 받은 앱은 Google이 다시 서명하므로 등록하지 않으면 Google 로그인이 실패한다). 로컬 디버그 키와 EAS 키는 등록해 두었다.
  - RevenueCat: 앱·상품, entitlement `cloud`, current offering, 웹훅(`/billing/revenuecat`), 서비스 계정 권한
  - 서버 `CLOUD_BILLING_ENABLED=true`, `REVENUECAT_*`, 앱 `EXPO_PUBLIC_REVENUECAT_*_KEY`
  - 결제 없이 쓰던 테스트 계정은 상태가 `none`이라 결제를 켜면 페이월로 간다 (데이터는 남아 있다)
  - 유예 알림 이메일 (메일 서비스 선택 후)
  - 완료 기준: 샌드박스 계정으로 구독 → 백업 → 해지 → 읽기 전용 → 재구독 즉시 복구, 그리고 별도 계정으로 해지 → 30일 경과(시간 조작) → 삭제까지 확인
- 전체 QA: 양쪽 실기기에서 `docs/QA.md`를 진행하고 P0·P1을 통과한다. 위 항목의 '실기기에서 확인' 내용도 여기에 모아 두었다
- 스토어 심사 제출

### Phase 4 이후 — 공유 앨범

가족처럼 여러 사람이 하나의 앨범에 사진을 담고, 물리 앨범을 돌려 보듯 함께 보는 경험을 만든다. 개인 기록을 먼저 고르는 흐름은 유지하되, 공유 앨범 안에서도 [이 앨범에 사진 고르기]로 각자가 자신의 기기 사진을 담는다.

- `albums.visibility`: `personal | shared`, `album_members`: `album_id, user_id, role(owner|editor|viewer), joined_at`, `moments.author_user_id`를 추가한다. 기존 `album_moments`는 그대로 사진과 앨범만 잇는다.
- 사진 파일은 올린 기록당 한 번만 계정 공간에 보관하고, 여러 앨범은 연결만 둔다. 다른 구성원이 같은 앨범에 사진을 더해도 기존 사진 파일을 복사하지 않는다.
- 앨범 화면은 사진마다 `누가 담았는지`를 보여 주며, 새 사진·메모·참여자 변화를 활동으로 남긴다.
- 권한 기본값: 올린 사람은 자신의 사진을 삭제할 수 있고, 소유자는 앨범·참여자·모든 사진을 관리한다. 편집자는 사진을 담고 메모를 쓰되 다른 사람 사진을 삭제할 수 없다. 보는 사람은 보기·내려받기만 한다.
- 공유 앨범과 참여자·권한·작성자 정보는 Cloud 전용이다. 초대·나가기·소유자 이전·계정 삭제와 구독 만료 시의 사진 소유권·접근권 규칙, 서버 권한 검증, 활동 동기화 테스트를 함께 구현해야 한다.

여행 모드(좌표·시간으로 기록을 묶어 여행 사진첩 제안), 지도로 보기, AI 결정 보조, 검색, 화질 기준 하위 유료 등급은 공유 앨범 검증 뒤에 판단한다.

## 7. 지표

| 가설 | 지표 |
|---|---|
| 선택 과정에서 가치를 느낀다 | 하루 기록 완료율, 날짜당 선택 수 |
| 작은 사진첩이 다시 보기 쉽다 | 주간 사진첩 열람, 상세 보기 체류 |
| 노력이 작으면 반복한다 | 선택 1회 소요 시간, D7/D30 재방문 |
| 다시 보기가 기록을 부른다 | 다시 보기 직후 새 기록 비율 |
| 보관에 돈을 낼 만하다 | Local→Cloud 전환율, 페이월 이탈률, 해지율, 유예 중 재구독률 |

Local 사용자는 서버 계정이 없으므로 익명 이벤트만 수집한다. 사진과 메모 내용은 수집하지 않는다.

## 8. 리스크

- **사진 권한 거부·부분 허용:** 부분 허용 상태에서도 동작하고, "사진 추가 선택" 버튼 제공
- **대용량 갤러리 성능:** 날짜 범위 조회, 썸네일만 로드, FlashList
- **SDK 버전 뒤처짐:** SDK 54는 최신보다 뒤처져 있다. 출시 전(또는 스토어가 새 Xcode를 요구할 때) vernissage와 함께 Xcode와 SDK를 올린다
- **업로드 중단:** 대기열을 SQLite에 저장, 앱 재시작 시 재개, 와이파이 전용 옵션
- **기기 사진첩에서 원본을 지움:** 이 기기에만 보관한 기록은 사진이 보이지 않고 메모·장소·날짜만 남는다 (설정·상세 화면에서 미리 안내, 안전 보관 안내). 구독 전에 지운 사진은 올릴 수 없다
- **이 기기에만 보관하는 사용자의 기기 분실·변경:** 기록이 이어지지 않는다 (이 기기 전용). 구독 안내는 강요하지 않는 선에서
- **결제 상태 불일치:** 웹훅 원본 저장 + 주기적 RevenueCat 재조회로 보정
- **실수로 인한 삭제:** 삭제 작업은 `grace_until`을 다시 확인하고, 실행 직전 RevenueCat 재조회로 재구독 여부 확인
- **개인 사진 보안:** 비공개 버킷, 짧은 만료 presigned URL, 사용자별 prefix, 서버 로그에 메모 내용 미기록

## 9. 미정 사항

- Apple 로그인 계정의 Android 복원: Apple 로그인은 iOS에만 있어 Apple 계정의 Cloud 데이터를 Android에서 받을 수 없다. Android에도 Apple 로그인을 넣을지, 이대로 안내할지 정한다
- Cloud 구독 가격, 용량 한도 (출시 전 원가·경쟁 앱 가격 조사 후 결정)
- 연간 구독 할인 여부, 무료 체험 기간
- 앱 화면 표시용 썸네일 크기
